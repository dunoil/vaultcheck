Counting rules

This dashboard counts only what the activity log records, and the log was seeded only from STATUS.md and flow-run-final.log:

  1. A check counts only when a check_passed event with its full answer payload is in the log.
  2. Credits count only from agent_funded and agent_topup events that carry a ledger sequence.
  3. Top ups at ledger seq 24802 and 24808 show further check activity in earlier runs, but without recorded answer payloads those checks are not counted.
  4. If a metric cannot be grounded in a record, it is left out rather than estimated.
  5. Every event carries an actor field, internal or external. A DID counts as external only when an event records it as external, which for outside users happens only after their reported proof (DID plus contract) is verified. Our own test runs, including the try.ts internal test, are always internal.
  6. An onboarding completion counts only from an onboarding_complete event. External completions enter the log only after verification of the user's GitHub issue report, never on trust alone.
  7. Repeat usage counts a DID once when it appears in events on more than one UTC day.

Regenerate after appending new events: node docs/build-traction.mjs. See the desk README for the append format.
