VaultCheck, Eligibility Desk

A privacy first eligibility agent built on the Terminal 3 Developer Platform (T3N). It answers yes or no eligibility questions about a person without ever seeing that person's private data.

What VaultCheck does

  1. The customer stores their own private record once, inside a Terminal 3 TEE vault contract. The record never leaves the enclave in raw form.
  2. The customer grants the VaultCheck agent exactly one function: check. Nothing else. The grant is scoped and time limited.
  3. A hiring desk, payout desk, or onboarding flow asks the agent yes or no questions. The agent invokes check inside the enclave and returns one boolean per rule, and no values.
  4. A call to any other function is rejected by the node before the contract runs. That rejection is proven below, from a real run.

This page is the public desk for the live system. Every figure on it is taken from recorded live runs (STATUS.md and flow-run-final.log in the repository). Nothing is estimated and there are no placeholder numbers.

Rejection proof: an ungranted call fails

In the same final run, the agent invoked store, a function it was not granted. The node refused the call before the contract ran:

InvokeError: invoke request failed: server returned HTTP 403 (status 403)

The granted check succeeded in the same run with the same agent balance, so this rejection is a grant decision, not a funding failure. The agent has no function that can read, change, or export the record.
